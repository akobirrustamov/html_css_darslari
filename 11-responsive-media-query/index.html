Reja 1 · Nazariya

Mobile-first va Desktop-first yondashuvlari

Saytni moslashuvchi qilishning ikkita yo'li bor. Farqni uy qurishga o'xshatish mumkin: desktop-first — katta uydan boshlab, keyin uni kichraytirish; mobile-first — kichik xonadan boshlab, kerak bo'lganda kengaytirish.

✓ Mobile-first

Avval eng kichik ekran (telefon) uchun bazaviy CSS yozamiz, keyin min-width bilan katta ekranlar uchun qo'shimcha stillar "qo'shib" boramiz.

/* Mobile-first: bazaviy stil - telefon uchun */
.container {
  display: block;
  padding: 16px;
}

/* Kattaroq ekranlar uchun qo'shimcha (min-width) */
@media (min-width: 768px) {
  .container {
    display: flex;
    padding: 32px;
  }
}
✗ Desktop-first (eski)

Avval katta ekran (kompyuter) uchun dizayn yozib, keyin kichik ekranlar uchun max-width bilan "tuzatishlar" qo'shib boramiz — eski, an'anaviy yondashuv.

Foydalanuvchilarning ko'pchiligi telefondan kiradi, va mobile-first yozilgan kod odatda soddaroq va tezroq yuklanadi — shu sabab yangi loyihalarda mobile-first ko'proq tanlanadi.

Talabalar ko'p adashadigan joy

Mobile-first bilan Desktop-first'ni aralashtirib, bir loyihada ham min-width, ham max-width ishlatib, breakpoint'lar bir-biriga zid kelib, natija oldindan aytib bo'lmaydigan bo'lib qoladi — bitta loyihada bittasini tanlab, oxirigacha o'shanga amal qiling.

Reja 2

viewport meta tegi — responsive'ning old sharti

Bu — bitta qatorlik kod, lekin usiz butun responsive dizayn ishlamaydi. Muammo shunda: telefonlar ekranlari kichik bo'lsa ham, saytlarni "kattalashtirib" (masalan 980px kenglikda) ko'rsatishga harakat qiladi — foydalanuvchi barmog'i bilan siqib-kattalashtirib o'qishga majbur bo'ladi.

<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Mening saytim</title>
</head>

Bu teg brauzerga "sun'iy kattalashtirma, sahifa kengligini qurilmaning haqiqiy kengligiga tengla" deb aytadi. U har doim <head> ichida, HTML faylning eng boshida bo'lishi shart — CSS'dagi @media qoidalari ham aynan shu teg to'g'ri qo'yilgandagina kutilganidek ishlaydi.

Talabalar ko'p adashadigan joy

Bu tegni umuman qo'shishni unutish — natijada @media qoidalarini to'g'ri yozgan bo'lsangiz ham, telefonda sayt hech qanday moslashmaganday ko'rinadi, chunki brauzer sahifani kattalashtirib ko'rsatib, "telefon ekrani kichik" degan holatga umuman kirmaydi.

Reja 3 · Sintaksis

@media — shart asosida CSS qo'llash

@media — bu CSS'ga "faqat mana bu shartda ishla" deyish usuli. Eng ko'p ishlatilgani — ekran kengligiga qarab: @media screen and (max-width: 768px) { ... } degani "ekran 768px yoki undan tor bo'lsa, shu ichidagi qoidalarni qo'll" degani.

.cards {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}
@media (min-width: 600px) {
  .cards {
    grid-template-columns: 1fr 1fr;
  }
}

@media (min-width: 1024px) {
  .cards {
    grid-template-columns: 1fr 1fr 1fr;
  }
}
Talabalar ko'p adashadigan joy

@media qoidalarini noto'g'ri tartibda yozish (masalan avval min-width: 1024px, keyin min-width: 600px) — CSS yuqoridan pastga o'qilgani uchun, keyingi qoida oldingisini "bosib" qo'yishi mumkin. Shu sabab breakpoint'larni kichikdan kattaga qarab tartib bilan yozish tavsiya etiladi (mobile-first yondashuvda).

Reja 3 · Breakpoint tanlash

Breakpoint — qaysi kenglikda dizayn o'zgaradi

Breakpoint (qaysi kenglikda dizayn o'zgarishi) tanlashda eng mashhur uchta chegara bor. Lekin muhim maslahat — breakpoint'ni "qurilma modeliga" emas, "kontentga" qarab tanlash kerak.

BreakpointOdatiy qurilma
~480pxKichik telefonlar
~768pxPlanshetlar
~1024pxKichik noutbuklar / katta planshetlar
Muhim maslahat

Sahifangizni sekin toraytiring va u qayerda "buzila boshlasa" (matn siqilib qolsa, ustunlar tiqilishib ketsa) — aynan o'sha yerga breakpoint qo'yiladi. Bir nechta @media qoidasini birga ishlatib, forma yoki karta layoutining telefon/planshet/desktop'dagi farqini jonli ko'ring.

Reja 4

Google Fonts (Google shriftlari) integratsiyasi

Standart shriftlar (Arial, Times New Roman) barcha saytlarda bir xil ko'rinadi va zamonaviy tuyulmaydi. Google Fonts — bepul, tayyor shriftlar to'plami: fonts.google.com saytiga kirib, kerakli shriftni tanlaymiz, u bizga tayyor <link> teg beradi — shuni HTML faylning <head> qismiga, boshqa stillardan OLDIN qo'shamiz.

<head>
  <link rel="preconnect" href="https://fonts.googleapis.com" />
  <link
    href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap"
    rel="stylesheet" />
</head>
body {
  font-family: "Inter", Arial, sans-serif;
}

Keyin CSS'da oddiy font-family orqali shu shriftni ishlatamiz, lekin har doim orqasidan zaxira (fallback) shrift ham yozib qo'yamiz — agar internet sekin bo'lsa yoki shrift yuklanmasa, brauzer eng yaqin oddiy shriftga o'tadi.

Talabalar ko'p adashadigan joy

Google Fonts saytida shrift tanlaganda faqat kerakli og'irliklarni (weight, masalan 400 va 700) tanlash kerak — hammasini (barcha qalinliklarni) qo'shib yuborish sahifani sekinlashtiradi, chunki har bir qo'shimcha og'irlik alohida fayl bo'lib yuklanadi.

Best practice

Yaxshi amaliyot — qisqacha

  • viewport meta tegini hech qachon unutmang — bu responsive'ning birinchi sharti.
  • Bitta loyihada faqat bitta yondashuv tanlang: mobile-first (min-width) yoki desktop-first (max-width) — aralashtirmang.
  • @media qoidalarini kichikdan kattaga tartib bilan yozing.
  • Breakpoint'ni kontentga qarab tanlang, tayyor jadvaldan emas.
  • Google Fonts'dan faqat kerakli og'irliklarni (masalan 400 va 700) tanlang.
  • Har doim fallback shrift qoldiring: font-family: "Inter", Arial, sans-serif;
Xotira uchun formula

Bitta yondashuv, kontentga qarab breakpoint, har doim viewport, har doim fallback shrift. Shu to'rtta qoidani saqlasangiz, responsive dizaynda asosiy xatolarning oldini olasiz.

Amaliyot uchun poydevor

Forma asoslari — bugun birinchi marta forma yasaysiz

Bugungi vazifada birinchi marta <form> elementi bilan ishlaysiz. Shuning uchun asoslarni qisqacha tushuntiramiz — bu keyingi modullarda ham kerak bo'ladi.

🏷️

<label>

Inputning nomi/yorlig'i. for atributi orqali inputning id'siga bog'lanadi — shunda label'ga bosilganda ham input faollashadi.

⌨️

<input>

type="text", type="email", type="password" — turli xil kiritish maydonlari.

📨

<button>

type="submit" — formani yuborish tugmasi.

<form>
  <label for="ism">Ismingiz</label>
  <input type="text" id="ism" name="ism">

  <label for="email">Email</label>
  <input type="email" id="email" name="email">

  <button type="submit">Yuborish</button>
</form>
Nega bu muhim

label va input'ni for/id orqali bog'lash shunchaki qulaylik emas — bu ekran o'quvchilari (screen reader) va foydalanuvchi tajribasi uchun ham muhim odat.

Savol-javob

1. Mobile-first va desktop-first yondashuvlari orasidagi asosiy farq nima?

Mobile-first — avval kichik ekran (telefon) uchun bazaviy CSS yozib, min-width bilan katta ekranlarga qo'shimcha stillar qo'shiladi. Desktop-first — aksincha, avval katta ekran uchun yozib, max-width bilan kichik ekranlar uchun tuzatishlar qo'shiladi. Yangi loyihalarda mobile-first tavsiya etiladi.

2. viewport meta tegi bo'lmasa, telefonda nima sodir bo'ladi?

Brauzer sahifani xuddi kengroq (taxminan 980px) desktop sifatida chizib, keyin uni butunligicha kichraytirib ko'rsatadi. Natijada matn juda mayda bo'lib ko'rinadi, garchi CSS'da xato bo'lmasa ham.

3. Breakpoint qiymatini qanday tanlash kerak?

"Qurilma modeliga" emas, "kontentga" qarab: sahifani sekin toraytirib, u qayerda "buzila boshlasa" (matn siqilib qolsa, ustunlar tiqilishib ketsa) — aynan o'sha yerga breakpoint qo'yiladi. Odatiy yo'l ko'rsatkich sifatida ~480px, ~768px, ~1024px ishlatiladi.

4. Google Fonts'dan shrift ulaganda nimaga e'tibor berish kerak?

Faqat kerakli og'irliklarni (weight, masalan 400 va 700) tanlash kerak — hammasini qo'shib yuborish sahifani sekinlashtiradi, chunki har bir qo'shimcha og'irlik alohida fayl bo'lib yuklanadi. Shuningdek, font-family'da har doim fallback shrift qoldirish kerak.

5. <label for="..."> nima uchun kerak?

Label'ni for atributi orqali inputning id'siga bog'lash uchun — shunda foydalanuvchi label matniga bossa ham, mos input faollashadi. Bu qulaylik va ekran o'quvchilari uchun muhim odat.
